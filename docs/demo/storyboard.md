# Storyboard — "Continue a Claude Code task in DSH" (~60 s)

Every frame below is a step of `run-demo.sh`, so the recording can be made
without staging anything: run the script, capture the terminal, cut it to this
order. Nothing is simulated and no tool output is faked.

**Setup before recording**

```sh
git clone https://github.com/HarryHeYu/dsh-sessionflow && cd dsh-sessionflow
# terminal: ~100x30, dark theme, font >= 16px
PYTHON=python3 bash docs/demo/run-demo.sh /tmp/sf-demo
```

Record at 1440×900 (or 2× for retina), then export a GIF at ~12 fps, ≤ 8 MB.
Trim the `=== 1.` build step to a single line — it is setup, not story.

## Shot notes

- **Frames 2–4 and 7 come straight from `run-demo.sh`.** Scroll the terminal; do
  not retype commands — a retyped command that fails on camera is the classic
  demo failure.
- **Frame 5–6 need a model provider.** If none is configured, replace it with a
  screen recording of `dsh --profile web --dump-config | grep dsh-sessionflow`
  plus the tool list, and label the caption *"agent turn — see
  docs/p8-live-verification.md"*. Do **not** present a fabricated tool call.
- **Do not claim native resume.** If the caption mentions resume at all, say the
  command is built but unverified.
- Keep the cursor visible; hover the `TODO:` line in frame 4 and the candidate
  list in frame 7 so the viewer's eye lands on the point.
- Blur or avoid nothing: the demo root is synthetic, so there is nothing private
  on screen. If you record in your own shell, still use `run-demo.sh` — never
  your real `~/.voyager`.
